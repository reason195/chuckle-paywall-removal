offsets from 1.1.1(154) were reused.

## IMPORTANT — "请求失败 / timeline shows days-old content" is NOT a patch bug

After some hours of use, pull-to-refresh produced a `请求失败` toast and stale
tweets. logcat proved it was an X-side auth failure, not the mod:

```
I g3f : REQUEST:  https://api.x.com/graphql/.../HomeTimeline   METHOD: POST
I g3f : RESPONSE: 403
I g3f : REQUEST:  https://api.twitter.com/2/badge_count/badge_count.json
I g3f : RESPONSE: 403
D NotificationObserver: onNotification: [请求失败, Chuckle]  (android.widget.Toast)
```

- **Both** X endpoints returned 403; DNS/TCP were fine, no app exception, `FATAL=0`.
- Re-login (or switching account) restores refreshing immediately — confirmed by
  the user. The X session/guest token simply expired.
- Nothing in the patch set touches OkHttp, GraphQL, auth headers, cookies or the
  timeline repository. The only network-adjacent patch is the *local* theme
  integrity predicate, which was already required for re-signing in 154.
- Diagnosis recipe: `adb logcat -d | grep 'g3f'` → look at `RESPONSE:` lines.
  403 on several unrelated X endpoints + stale cached timeline = expired login,
  **not** a broken build. Do not re-patch; just re-login.
